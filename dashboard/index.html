Threshold selection

instruct.md's "Important Consideration"

False positives waste retention spend on customers who weren't leaving; false negatives lose the customer's full value. Because FN cost scales with each customer's actual value while FP cost is a flat assumed outreach cost (50 units — a placeholder pending real campaign figures), the cost-minimizing threshold sits below the default 0.5.

Methodology & assumptions

  • Deduplication: 300 exact-duplicate rows (9.5% of raw data) dropped before any split or training.
  • Age field: raw Age was a 1:1 restatement of Age Group (only 5 distinct values) — dropped as redundant.
  • status excluded from modeling: churn rate is 5.6% at status=1 vs 47.5% at status=2 — the strongest relationship in the dataset and a likely leakage signal, since it isn't confirmed to be set before the churn outcome.
  • Dormant customers: 85 customers (3.0%) with zero usage and zero value are flagged, not dropped — handled as a separate watchlist rather than folded into the value-ranked list.
  • Class imbalance (15.6% churn) handled via class weighting in every model, not synthetic resampling, given the dataset's already-small size.
  • Deployment scoring: the risk list is scored by a model refit on the full dataset, so its own training rows score optimistically — an accepted limitation of scoring your own customer base; it does not affect the test-set metrics shown above.
Placeholder assumption

False-positive cost is set to a flat 50 units per contacted customer for the threshold sweep above. This is not a real campaign cost — replace it with the business's actual retention-outreach cost and re-derive the threshold.
